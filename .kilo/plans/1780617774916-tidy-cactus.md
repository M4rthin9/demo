# Administrative Dashboard Enhancement Plan

## Overview
Enhance the existing admin.html dashboard with:
1. Complete visitor CRUD management
2. Full user and role management system
3. Settings module for password updates

## Current State Analysis
- **Existing Features**: Login, dashboard metrics, reservations table, reports, event log, basic user management (create only)
- **Backend**: Google Apps Script API with actions: login, getAll, updateStatus, createUser, getUsers, getRoles
- **Missing Features**: Visitor CRUD, Edit/Delete users, Password change, Dedicated settings page

## Implementation Plan

### Phase 1: Visitor CRUD Management

#### 1.1 Add Visitors Management View
- Add new sidebar menu item: `ผู้เยี่ยม` (Visitors) - visible to Superadmin/Admin only
- Create `view-visitors` section with:
  - Search/filter controls
  - Visitors table with columns: ชื่อ, บัตรประชาชน, โทรศัพท์, อีเมล, ความสัมพันธ์, การกระทำ
  - Add/Edit/Delete buttons with modals
  - Integration: Add visitors to bookings via booking form

#### 1.2 Visitor Data Structure
```javascript
visitor = {
  id: 'unique-id',
  name: 'string',
  idCard: 'string',
  phone: 'string',
  email: 'string',
  relation: 'string',
  createdAt: 'datetime',
  updatedAt: 'datetime'
}
```

#### 1.3 CRUD Operations
- **Create**: Form modal with validation
- **Read**: Paginated table with search/filter
- **Update**: Inline edit or modal form
- **Delete**: Confirmation dialog with soft-delete option

### Phase 2: User & Role Management

#### 2.1 Users Management View
- Add sidebar menu item: `ผู้ใช้` (Users) - visible to Superadmin/Admin only
- Create `view-users` section with enhanced features:
  - Edit user modal: username, displayName, role, active status
  - Delete user with confirmation
  - Reset password functionality

#### 2.2 Roles Management View
- Add sidebar menu item: `บทบาท` (Roles) - visible to Superadmin only
- Create `view-roles` section with:
  - Role list table showing predefined roles (Superadmin, Admin, Finance, Vinai, Tadtel, User)
  - Permissions display per role (read-only, based on PERMISSIONS config)
  - Note: Predefined roles only - no custom role creation/deletion

#### 2.3 Update Backend Actions Needed
- `getUsers` - Already exists
- `getUser` - Get single user
- `updateUser` - Update user details
- `deleteUser` - Delete user
- `createRole` - Create new role
- `getRoles` - Already exists, enhance to include permissions
- `updateRole` - Update role permissions
- `deleteRole` - Delete role
- `changePassword` - New: for users to change own password

### Phase 3: Settings Module

#### 3.1 Settings View
- Add sidebar menu item: `ตั้งค่า` (Settings) - visible to all authenticated users
- Create `view-settings` section with tabs:
  - ข้อมูลส่วนตัว (Profile): view/edit display name
  - เปลี่ยนรหัสผ่าน (Change Password): current + new + confirm password
  - การตั้งค่า (Preferences): theme, language, notifications

#### 3.2 Password Change Implementation
- Frontend validation (current password required, new password min 6 chars)
- Backend: `changePassword` action
- Secure update via API

### Phase 4: UI/UX Improvements

#### 4.1 Navigation Updates
- Update `SIDEBAR_MENU` in admin.js:
```javascript
Superadmin: ['home', 'reservations', 'visitors', 'users', 'roles', 'reports', 'eventlog', 'settings'],
Admin: ['home', 'reservations', 'visitors', 'users', 'reports', 'eventlog', 'settings'],
Finance: ['reservations', 'reports'],
Vinai: ['reservations', 'reports'],
Tadtel: ['reservations', 'reports']
```

#### 4.2 Permission Updates
- Add `manage_visitors` permission
- Update PERMISSIONS object accordingly

### Phase 5: Enhanced Charts for Overview Page

#### 5.1 Additional Chart Visualizations
- **Wing Distribution Chart**: Pie/doughnut chart showing visitors per wing (แดน)
- **Daily Traffic Chart**: Bar chart showing booking counts by hour of day
- **Approval Status Donut**: Visual breakdown of approval pipeline stages
- **Payment Status Chart**: Donut chart for payment tracking (paid/unpaid/pending)

#### 5.2 Chart Layout Changes
- Reorganize `dash-grid` to accommodate additional charts
- Add new canvas elements for each chart type
- Implement responsive chart sizing for mobile/desktop

#### 5.3 Chart Data Calculations
- Wing distribution: Count bookings per wing, show percentage
- Hourly traffic: Aggregate timestamp hours to show peak booking times
- Status pipeline: Multi-stage funnel visualization
- Payment distribution: Financial summary with visual breakdown

### File Changes Required

| File | Changes |
|------|---------|
| admin.html | Add visitors/users/roles/settings views, modals, additional chart canvases |
| src/js/admin.js | Add CRUD functions, API calls, data management, enhanced chart rendering |

### API Endpoints to Implement (Backend)
1. `getVisitors` - Fetch all visitors
2. `createVisitor` - Create new visitor
3. `updateVisitor` - Update visitor
4. `deleteVisitor` - Delete visitor
5. `updateUser` - Update user details
6. `deleteUser` - Delete user
7. `changePassword` - Change user password

### Backend Modifications Required
The Google Apps Script backend needs to implement the above API endpoints to handle visitor CRUD operations and user management updates.

## Implementation Order
1. Settings view with password change (simplest, standalone)
2. Enhanced overview charts (Wing distribution, Hourly traffic, Payment status)
3. Visitor CRUD (reuses table patterns, integrates with bookings)
4. User edit/delete (reuse visitor patterns)
5. Role view (read-only display of predefined roles)

## Notes
- Demo mode: Data stored in localStorage when backend unavailable
- API calls follow existing pattern: POST to APPS_SCRIPT_URL with JSON body
- UI follows existing design system (Sarabun font, navy/gold colors)
